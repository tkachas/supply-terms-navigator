# CLAUDE.md — контекст проекта для ИИ-агента

Прототип сверки условий договоров поставки. Пользователь — закупщик: ему нужны сумма
и срок поставки на дату проверки, и каждое значение он должен проверить по исходному тексту.

## Команды

```bash
python -m unittest discover -s tests -t .          # все тесты (stdlib, без pytest)
python -m terms_navigator check documents          # таблица по договорам в консоли
python -m terms_navigator ask documents amount STN-102
python -m terms_navigator serve --port 8000        # веб-интерфейс
```

Внешних зависимостей нет — не добавляй их без явной просьбы.

## Архитектура (поток данных)

`text.py` (декодирование, абзацы, предложения, даты/суммы)
→ `classify.py` (тип документа, номер, ссылки на договор, статус подписания, дата вступления в силу)
→ `fields.py` (реестр полей: как найти значение в договоре и в формулировке изменения)
→ `resolve.py` (связывание документов, применение ДС на дату проверки, несогласованные изменения)
→ `queries.py` (ответы на вопросы) → `serialize.py` → `server.py` / `__main__.py` / `static/`.

## Инварианты — не нарушать

1. **Нет значения без цитаты.** Любое `FieldValue.value` сопровождается `Evidence`, где
   `quote == paragraph.text[start:end]`. Тест `test_every_value_has_exact_quote` это проверяет.
2. **Нет данных — значит `None`, а не догадка.** Лимиты, авансы, сроки оплаты — не сумма и не срок
   поставки; они попадают в `other_mentions` с причиной.
3. **Условия меняет только ДС, подписанное обеими сторонами и вступившее в силу к дате проверки.**
   Проекты, письма, ДС с будущей датой — только в `pending`. Неясный статус → `needs_review`.
4. **Имя файла и порядок загрузки ничего не значат.** Тип и приоритет — только по содержимому.
5. В логике извлечения нельзя упоминать конкретные номера договоров, суммы и даты из
   `documents/`. Допустимы только тесты и пресеты четырёх вопросов задания в UI (это параметры
   запроса, не ответы). На демо загрузят изменённые и новые файлы.

## Как добавить поле (например, ставку неустойки)

1. В `fields.py` написать три функции уровня предложения: `find` (формулировка договора),
   `find_proposal` (формулировка изменения, обычно через `_proposal_hits`), `mentions` (что
   похоже, но значением не является — можно `_no_hits`). Возвращают `Hit` со смещениями
   **внутри предложения**.
2. Добавить `FieldSpec(...)` в `FIELDS` (с `fmt` и `topic` для объяснения «нет данных»).
   Разрешение изменений, цитаты, JSON и CLI подхватят поле автоматически.
3. В UI (`static/app.js`) — колонка в `renderContracts` и пункт в `#qType`, если нужен вопрос.
4. Тесты: положительный случай на учебном наборе + минимум один отрицательный
   (похожее число в другом контексте) + «нет данных».

Шаблон задачи для агента: `.claude/commands/add-field.md`.

## Стиль

- Пользовательские тексты, комментарии и сообщения — на русском.
- Регулярные выражения — именованные константы на уровне модуля с комментарием, что они ловят.
- Перед изменением экстрактора сначала добавь падающий тест с реальной формулировкой.
